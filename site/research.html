How it works

Nilmo is a hosted MCP gateway for Solana mainnet-beta. You add one URL to your AI client, and from then on you can ask it to read balances, inspect accounts and transaction history, check signatures, and simulate provided transactions. This page walks through what happens between your question and the answer.

Endpointhttps://nilmo-solana-mcp.vercel.app/mcp
NetworkSolana mainnet-beta
ReadsFree, and need no wallet
MCP in one paragraph

MCP, the Model Context Protocol, is an open protocol for connecting AI clients to tools. A client that supports it, such as Claude, Claude Code, ChatGPT, Cursor, VS Code or Devin Desktop, can be pointed at an MCP server and will then see that server's tools, with a description of what each one does and what it needs. When you ask for something, the AI decides which tool fits, calls it, and uses the answer in its reply. Nilmo is an MCP server built for on-chain networks, and Solana is the first network it serves.

01

The path of a request

What happens after you ask a question in your AI client.

01 · You ask

You type a request in your AI client in plain words, for example “why did my last deposit fail?”.

Your AI client
02 · A tool is picked

The client already knows Nilmo's tools and their inputs, so the AI chooses the ones that fit, here solana_get_transaction and solana_trace_call, and fills in the hash.

MCP tool call
03 · Nilmo works

Nilmo validates the request, calls Solana RPC and returns structured chain data the AI client can use.

Solana RPC
04 · Back to you

The AI answers in the chat using the structured result. Simulation results include logs and errors, but Nilmo does not sign or send the transaction.

Planned wallet flow

Not part of the current public beta. Nilmo never holds private keys or asks for a seed phrase.

Planned wallet-action flow
You Send 25 SOL to 7VbW…kP3 AI calls solana_prepare_transaction Nilmo simulates it against live state to 7VbW…kP3 value 25 SOL fee from solana_estimate_fees result succeeds, sends 25 SOL You open the signing link, check it, sign in your wallet Wallet sends it to Solana AI calls solana_wait and reports the result
Planned

Simulated, then signed by you

Anything that changes state comes back as an unsigned transaction with a plain preview of what it will do. You review it and sign it in your own wallet, and only then does Nilmo broadcast it.

Planned

An agent key with limits

For agents that run without asking each time, you create an agent key in your own wallet, fund it and set hard limits. The agent can act inside those limits only, and you can revoke the key at any time.

Each network gets its own endpoint, such as https://nilmo-solana-mcp.vercel.app/mcp, so you choose exactly which chains your AI can reach.

Same tools, same limits

Tool shapes, agent wallets, signing and rate limits work the same way on every network, so an agent built for Solana carries over without a rewrite.
